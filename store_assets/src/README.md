# Store asset sources — read this before regenerating anything

Everything in `store_assets/` was generated by the scripts in this folder
(originally run from a Claude Code session scratchpad on 2026-08-26).
This file records what a future session needs to know to redo or extend the
work without re-discovering it.

## What's in the parent folder

- `store-description.txt` — Chrome Web Store listing description (plain text,
  no markdown). Feature claims come from CHANGELOG.md; the measured
  numbers (~0.8 s first marks, ~6 s / thousands of marks for a news homepage,
  12 MB install) come from the e2e benchmarks recorded there. Update these if
  performance changes.
- `screenshot-1..5.png` — 1280×800, 24-bit PNG, **no alpha** (store rejects
  alpha in screenshots; icons may keep alpha).
  1. Hero: real Arabic news main headline before/after (navy brand background)
  2. Whole-page mode: Arabic Wikipedia "اللغة العربية" before/after + magnifier lens
  3. Invocation methods over the dotted news page (menu, keycaps, icon callout)
  4. Paste page with real dotted output + 1-2-3 steps
  5. Privacy/speed card grid with the measured stats
- `promo-tile-440x280.png` — brand tile with العربية → الْعَرَبِيَةَ demo chip.
- `icons/alif_{16,32,48,128,512}.png` — the extension/store icon.
  Adopt in the extension with `cp store_assets/icons/alif_{16,32,48,128}.png images/`.

## How the pipeline works (three stages)

1. **Capture** (`capture.mjs` full pages, `capture2.mjs`/`capture3.mjs`
   element close-ups): loads the built extension into real Chrome via
   puppeteer and screenshots LIVE pages before/after actually running it.
   Raw PNGs land in a `raw/` dir next to the scripts.
2. **Compose** (`shot1..5.html` + `compose.mjs`, `tile.html`): each store
   image is an HTML page that embeds the raw captures (relative paths
   `raw/...` and `final/icons/...`); `compose.mjs` renders it at
   deviceScaleFactor 2 and sharp-downscales to the exact store size, then
   `.flatten().removeAlpha()` for 24-bit output. Usage:
   `node compose.mjs shotN.html out.png [w=1280] [h=800]`.
3. **Icon** (`icon-final.html` + `make-icons.mjs`): renders the SVG icon at
   512 px and lanczos-downscales to every size. `render.mjs` is a generic
   HTML→PNG helper (used for icon variant sheets).

## Hard-won gotchas (this is the time-saving part)

- **Paths**: every script hardcodes two absolute paths — the repo root
  (`REPO`, the repo root itself) and the output dir (`OUT`, which is
  `store_assets/src/raw/` — gitignored scratch, never committed). Fix those
  first; nothing else needs changing.
- **Dependencies**: run `npm run build` first (scripts load `dist/`).
  puppeteer comes from the repo's node_modules — run the scripts from
  inside the repo so it resolves. `sharp` is NOT a repo dependency;
  `npm i --no-save sharp` from the repo root (don't add it to package.json).
- **Icon**: `compose.mjs` and the shot HTML embed `final/icons/alif_*.png`
  (relative to `store_assets/src/`). If you're not regenerating icons with
  `make-icons.mjs`, just copy the shipped ones there first:
  `mkdir -p store_assets/src/final/icons && cp store_assets/icons/alif_*.png store_assets/src/final/icons/`.
- **Extension permissions**: the shipped manifest has only `activeTab`,
  which requires a real user gesture automation can't produce. The capture
  scripts copy `dist/` to a temp dir and add
  `host_permissions: ["<all_urls>"]` (same trick as `e2e/extension.test.mjs`).
- **Invoking the extension**: get the service-worker target
  (`t.type() === 'service_worker' && url includes background.js`), then
  `sw.evaluate`. **Do NOT** call `chrome.scripting.executeScript` with
  `content.js` directly — with the current extension that bypasses the
  selection/whole-page handshake and barely dots the page. Drive the
  extension's REAL entrypoint instead, exactly like `e2e/extension.test.mjs`:
  `globalThis.__tashkeelInvokeWholePage(tab)` (whole page, ignores any
  selection) or `globalThis.__tashkeelInvoke(tab, file)`. Match the tab by the
  raw or `decodeURIComponent(tab.url)` form — Arabic URLs are percent-encoded
  and won't match otherwise.
- **Waiting for completion**: results stream in. The content script sets
  `data-tashkeel-busy` on `<html>` while running; arm a run by removing that
  attribute, invoke, then poll until it's gone (with a mark-count fallback).
  Mark counting uses the Arabic tashkeel range `[ً-ْ]` (U+064B..U+0652,
  matching `TASHKEEL_RE` in `text_encoding.mjs`; excludes U+0670) in
  `document.body.innerText`. Copied from the e2e test.
- **Headless works**: extensions + service workers run fine under
  `headless: true` in the pinned puppeteer. Add `--font-render-hinting=none`
  for clean text.
- **DPR**: full pages captured at deviceScaleFactor 2, element close-ups
  at 3 (they get displayed enlarged in compositions).
- **Diacritic clipping**: element screenshots clip tashkeel! Marks extend
  above/below the element's bounding box. Fix: set
  `element.style.padding = '18px 8px'` before shooting (capture3.mjs does
  this). A plain clip-padding of 8–14 px was not enough on the news headline.
- **Before/after must come from one page session** — take "before", run the
  extension, take "after" without reloading, or live-site content (ad
  banners, news tickers) won't match between the two shots.
- **Page cleanup**: `cleanPage()` strips cookie/consent/taboola elements and
  freezes CSS animations. In shot3.html the news site's top bar is cropped
  out with `margin-top: -86px` on the page image — recheck that offset if
  recapturing (it's a dimmed background behind the callout cards, so the exact
  value is not critical).
- **Bot walls**: some Arabic news sites (notably Al Arabiya) serve a Cloudflare
  "complete the security check" interstitial to headless Chrome — which
  otherwise looks like a valid page with a headline. The capture scripts guard
  against this by requiring >400 Arabic chars of real body text before
  accepting a site, and fall back down a list. **Aljazeera is deliberately
  excluded from the screenshots** (editorial decision); it may still appear in
  test fixtures.
- **Demo pages that work well**: Arabic Wikipedia "اللغة العربية"
  (`ar.wikipedia.org/wiki/اللغة_العربية`) is stable, neutral, and thematically
  perfect (the article about Arabic itself; tens of thousands of marks when
  fully dotted). An Arabic news homepage (Al Arabiya first, then Asharq
  Al-Awsat `aawsat.com`, BBC Arabic, Sky News Arabia) works live but the
  headline is that day's (possibly political) news — screenshots 1 and 3 date
  accordingly; rerun `capture3.mjs`/`capture.mjs` to refresh. The paste page is
  at `chrome-extension://<extId>/paste.html` (fill `#input`, click `#run`, wait
  for marks in `#output`).
- **Context-menu labels in shot3.html are hand-recreated** (native menus
  can't be screenshotted). They must match `background.js` exactly —
  currently "Add tashkeel (أضف تشكيل)", "Add tashkeel to the whole page",
  "Remove tashkeel (أزل تشكيل)", "Open paste page (works in Google Docs etc.)".
- **Google Fonts load fine** in the composition renders (network is on):
  Inter for UI text. (The shot HTML still references Frank Ruhl Libre for the
  faint background watermark glyph; it carries no Arabic glyphs, so that large
  `بَ` falls back to a system Arabic face — cosmetic only. Swap it for an
  Arabic display face such as Amiri if a crisper watermark is wanted.)

## Design decisions (keep consistent)

- **Brand palette**: navy `#172554`/`#0b1533` (dark bg gradient), blue
  `#2563eb`, gold accent `#facc15`; light shots use
  `linear-gradient(#f2f6fc, #e3ebf7)`. Screenshots alternate
  navy (1, 5) / light (2, 3, 4) as bookends.
- **Icon**: Amiri 700 baa `ب` (font-size 0.72×), white on
  `#172554→#2563eb` gradient, corner radius 27/128, subtle radial glow, and a
  hand-drawn gold fatha (rounded diagonal bar) above the letter — the fatha
  is the point: the icon shows a vowel mark being added. Prefer an Arabic
  serif/naskh face with clear 16/32/48 px legibility on light and dark
  toolbar mocks (see `render.mjs` + the icon*.html variant sheets pattern).
  NOTE: the shipped `alif_*.png` were generated separately; `icon-final.html`
  is a reference — reconcile against the shipped PNGs before regenerating.
- **Store constraints** (why outputs are shaped this way): max 5 screenshots,
  1280×800 or 640×400, JPEG or 24-bit PNG **no alpha**; small promo tile
  440×280; store icon 128×128 (alpha OK). `compose.mjs` verifies by printing
  channels/alpha — screenshots must say `channels: 3 alpha: false`.
